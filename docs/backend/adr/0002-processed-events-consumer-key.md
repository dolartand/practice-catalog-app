# ADR 0002. Идемпотентность консьюмеров: unique (consumer, event_id)

## Статус

Принято

## Контекст

[06-events.md] и [10-development-tasks.md, блок 6] требуют таблицы `processed_events` с «unique-индексом на event_id» для идемпотентности обработки событий Kafka.

Система имеет несколько независимых консьюмеров (catalog-cache, review-rating, order-sink). Если они пишут обработанные `event_id` в одну таблицу с ограничением unique(event_id), то первое же дублирующее событие, полученное вторым консьюмером, вызовет конфликт вставки и будет ошибочно пропущено как «уже обработанное» другим консьюмером.

## Решение

Добавить колонку `consumer varchar(100) NOT NULL` и уникальный индекс `(consumer, event_id)`:

```sql
CREATE UNIQUE INDEX uk_processed_events_consumer_event ON processed_events (consumer, event_id);
```

Каждый консьюмер проверяет и фиксирует обработку события в своём пространстве ключей.

## Последствия

- Один и тот же `event_id` может быть зафиксирован каждым консьюмером ровно один раз.
- Повторная доставка события внутри одного консьюмера не приводит к повторному эффекту.
