# 07. Кэширование и медиа

> Статус: черновик
> Версия: 0.1
> Связанные документы: [01. Архитектура](01-architecture.md), [02. Модель данных](02-domain-model.md), [03. Дизайн API](03-api-design.md), [06. События](06-events.md)

## 1. Redis в v1

- **Назначение:** только кэш чтения каталога (категории, списки, карточки товаров).
- **Уточнение к [06-events.md](06-events.md):** идемпотентная обработка Kafka-событий в v1 выполняется через **unique-индекс в БД** (таблица `processed_events` с `event_id`), а не через Redis, — Redis в v1 не используется для других целей. Переход на Redis для идемпотентности — при появлении рейт-лимитов и других нужд (roadmap).
- **Конфигурация:** ключи с TTL, namespace `catalog:`. Redis не является источником истины — сбой Redis деградирует производительность, но не корректность (данные читаются из PostgreSQL).

## 2. Кэш чтения каталога

### Ключи

| Ключ | Содержимое | TTL |
|---|---|---|
| `catalog:categories:tree` | Дерево активных категорий (ответ GET /categories) | 5 мин |
| `catalog:products:list:{hash}:{page}:{size}` | Страница списка товаров для конкретной комбинации параметров (без остатков) | 5 мин |
| `catalog:product:{id}` | Карточка товара (без остатков): поля, изображения, SKU-метаданные, рейтинг | 5 мин |

- `hash` — детерминированный хэш параметров запроса (`q`, `categoryId`, `priceFrom/To`, `series`, `type`, `sort`, исключая `page`/`size`).
- **Negative cache:** пустой результат списка кэшируется на 60 секунд (защита от «горячих» пустых запросов и создания мусорных ключей при переборе страниц).

### Остатки — всегда из БД

- Поле `inStock` в списках формируется при сборке ответа **batch-запросом к БД** по SKU товаров текущей страницы — кэшированный список остатков не содержит.
- `stockQty` в карточке товара читается из БД при каждом запросе (гарантия актуальности перед добавлением в корзину).
- Фильтры `inStock` / `onlyDiscounted` **не кэшируются**: запросы с этими параметрами выполняются напрямую к PostgreSQL (остатки вне кэша, инвалидация не требуется).

### Инвалидация

| Событие | Действие |
|---|---|
| `product.updated.v1` (Kafka) | удаление `catalog:product:{id}` и всех ключей `catalog:products:list:*` (изменение цены/активности влияет на списки) |
| `product.created.v1` (Kafka) | удаление всех ключей `catalog:products:list:*` |
| CRUD категорий (в том же приложении) | удаление `catalog:categories:tree` и всех ключей `catalog:products:list:*` |
| Истечение TTL | пассивная инвалидация (5 мин) |

- Инвалидация списков целиком по namespace (`SCAN` + `DEL`) допустима при частоте событий до ~10/мин; при росте — переход на точечные ключи (в roadmap).
- Остатки не требуют инвалидации — они не кэшируются.

## 3. MinIO / изображения

### Доступ

- **Публичный бакет** `catalog-images` (policy `readonly`): постоянные URL без подписи — `https://cdn.example.com/catalog-images/products/{productId}/{file}.jpg`.
- Изображения доступны по прямой ссылке; для продакшена URL отдаются через отдельный домен/CDN (настраивается проксированием бакета).

### Структура ключей объектов

| Тип | Ключ |
|---|---|
| Товар | `products/{productId}/{uuid}.{ext}` |
| Категория | `categories/{uuid}.{ext}` |

- `uuid` генерируется при загрузке; имя файла клиента не используется (защита от коллизий и инъекций в ключ).

### Валидация и метаданные

| Правило | Значение |
|---|---|
| Форматы | JPEG, PNG, WebP |
| Размер | до 10 МБ |
| Метаданные | `Content-Type` по расширению, `Cache-Control: public, max-age=31536000, immutable` (URL неизменяем — изображение не перезаписывается) |

- Загрузка — через `POST /api/v1/admin/products/{id}/images` (multipart), детали в [03-api-design.md](03-api-design.md).
- Расширение файла сверяется с объявленным `Content-Type`; неизвестные типы отклоняются (400).

### Жизненный цикл файлов

| Сценарий | Поведение |
|---|---|
| `DELETE /api/v1/admin/images/{id}` | Удаление записи `product_images` **и** объекта из MinIO |
| Замена главного изображения | Новый объект загружается новым ключом, старый удаляется (только если не используется другими записями) |
| Soft delete товара | Запись изображения остаётся, объект **не удаляется** (заказ/история могут ссылаться на URL); очистка орфанных файлов — фоновая задача (roadmap) |

## 4. HTTP-кэширование для мобильного

- **Публичные ответы каталога** (`GET /categories`, `GET /products`, `GET /products/{id}`): `Cache-Control: public, max-age=300` (5 минут, совпадает с TTL кэша Redis).
- **Карточка товара:** дополнительно `ETag` (хэш содержимого) — клиент может слать `If-None-Match`, сервер отвечает `304 Not Modified`.
- **Ответы с остатками** (корзина, карточка с `stockQty`, списки с `inStock=true`): `Cache-Control: no-store` — не кэшируются ни клиентом, ни промежуточными прокси.
- **Авторизованные ответы** (заказы, избранное, профиль): `Cache-Control: private, no-store`.
