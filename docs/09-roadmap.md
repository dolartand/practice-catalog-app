# 09. Roadmap

> Статус: черновик
> Версия: 0.1
> Связанные документы: [01. Архитектура](01-architecture.md), [04. Аутентификация](04-auth.md), [06. События](06-events.md), [08. Запуск и окружения](08-setup.md)

## 1. Принципы планирования

- **v1 — единая версия** без разделения на MVP и полный функционал: выпускается целиком.
- План в этом документе — **порядок разработки** (последовательность работ), а не фазы с датами.
- **Без оценок трудоёмкости и календарных дат** — оценки добавляются в момент планирования спринтов.
- **v2 не планируется.** Любые расширения за рамки v1 оформляются отдельным решением (ADR) и добавляются в раздел 5 только после явного согласования.
- Критерий завершённости — чек-лист готовности (раздел 2); каждый шаг считается выполненным, когда код работает в окружении из [08-setup.md](08-setup.md) и покрыт тестами.

## 2. Объём v1 и критерии готовности (DoD)

Функциональные модули:

- [ ] Каталог: дерево категорий, товары с фиксированными характеристиками, SKU с остатками, изображения, поиск с фильтрами/сортировкой/пагинацией
- [ ] Auth: регистрация, вход, JWT access/refresh с ротацией, logout, смена пароля, роли USER/ADMIN
- [ ] Корзина: лимиты, пересчёт цен, недоступные позиции
- [ ] Заказы: оформление с атомарным списанием остатков, статусы NEW/CONFIRMED/DELIVERED/CANCELLED, отмена с возвратом остатков
- [ ] Избранное: добавление/удаление/список
- [ ] Отзывы и рейтинг: только покупатели (DELIVERED), один отзыв на товар, модерация, агрегат рейтинга
- [ ] Админка: CRUD категорий/товаров/SKU/изображений (MinIO), смена статусов заказов, модерация отзывов

Технические модули:

- [ ] PostgreSQL + Flyway (миграции V1+)
- [ ] Redis: кэш категорий/списков/карточек, TTL + событийная инвалидация
- [ ] Kafka: топики `catalog.events`, `order.events`, `review.events`; консьюмеры кэша и рейтинга; DLT
- [ ] MinIO: публичный бакет, загрузка/удаление изображений
- [ ] Обработка ошибок RFC 9457, валидация, MapStruct
- [ ] Actuator (health/info), structured-логи, traceId
- [ ] Тесты: юнит (JUnit 5 + Mockito), интеграционные (Testcontainers: PostgreSQL, Redis, Kafka, MinIO)
- [ ] Документация: README, docs/ (все разделы), openapi.yaml (фаза 2), ADR по принятым решениям (фаза 3)

Приёмка v1: мобильный клиент проходит сценарии «каталог → корзина → заказ → доставка → отзыв» и «админка: товар → изображение → подтверждение заказа» без ручных правок данных.

## 3. Порядок разработки

| № | Шаг | Состав работ | Результат |
|---|---|---|---|
| 1 | **Каркас** | Инициализация проекта (Spring Boot 4, Java 25, Maven), структура пакетов по модулям, application.yml + env, docker-compose, Flyway V1, обработка ошибок RFC 9457, Actuator, конвенции из [01-architecture.md](01-architecture.md) | Приложение поднимается, `/actuator/health` — UP, инфраструктура из compose работает |
| 2 | **Каталог (чтение)** | Модель данных (см. [02-domain-model.md](02-domain-model.md)): категории, товары, SKU, изображения; GET-эндпоинты с фильтрами/сортировкой/пагинацией; полный ответ списка и карточки | Публичный каталог доступен без авторизации |
| 3 | **Auth** | Регистрация, вход, JWT access/refresh с ротацией, logout, смена пароля, роли, seed админа; защита эндпоинтов | Все защищённые эндпоинты работают по ролям |
| 4 | **Корзина и заказы** | Корзина с лимитами, оформление заказа одной транзакцией (списание остатков, SELECT FOR UPDATE), статусы и переходы, отмена с возвратом остатков | Полный цикл заказа работает |
| 5 | **Избранное, отзывы, рейтинг** | Избранное, отзывы (проверка покупки по DELIVERED, модерация), агрегат рейтинга | Пользователь может оставить отзыв после доставки |
| 6 | **Админка** | CRUD категорий/товаров/SKU, загрузка и управление изображениями (MinIO), смена статусов заказов, модерация отзывов | Полный контур управления из [03-api-design.md](03-api-design.md) |
| 7 | **Redis-кэш и Kafka** | Кэш чтения каталога с инвалидацией по событиям; топики и консьюмеры; DLT и идемпотентность; пересчёт рейтинга по событию | Кэш и события работают по [06-events.md](06-events.md) и [07-caching-and-media.md](07-caching-and-media.md) |
| 8 | **Качество и документация** | Полный прогон `mvnw test` (Testcontainers), покрытие сервисов ≥ 80%, openapi.yaml, README, проверка DoD-чек-листа | v1 готова к приёмке |

Зависимости: каждый шаг опирается на предыдущий (код не может быть протестирован в полном сценарии раньше шага 7); шаг 8 финализирует.

## 4. Зафиксированные упрощения v1 и условия их закрытия

| Упрощение | Где зафиксировано | Что требуется для закрытия |
|---|---|---|
| Публикация событий без transactional outbox (риск потери при сбое между COMMIT и публикацией) | [06-events.md](06-events.md), раздел 1 | Внедрение таблицы outbox + релизера (Kafka producer на фоне) |
| Без SMTP: нет верификации email, восстановления пароля, писем | [04-auth.md](04-auth.md), раздел 6 | Подключение SMTP, одноразовые коды, шаблоны писем |
| Без рейт-лимитов на login/register | [04-auth.md](04-auth.md), раздел 6 | Рейт-лимиты на Redis (готовый компонент, включается конфигурацией) |
| Без Prometheus/Grafana | [01-architecture.md](01-architecture.md), раздел 8 | Развёртывание Prometheus, дашборды, алерты |
| Орфанные файлы MinIO не очищаются | [07-caching-and-media.md](07-caching-and-media.md), раздел 3 | Фоновая задача сверки `product_images` и объектов бакета |
| Идемпотентность событий через таблицу БД (не Redis) | [07-caching-and-media.md](07-caching-and-media.md), раздел 1 | Перенос на Redis при появлении других применений Redis |
| Инвалидация списков целиком (namespace) | [07-caching-and-media.md](07-caching-and-media.md), раздел 2 | Точечные ключи при росте частоты событий |
| Полная история статусов заказа — только `status_history` JSONB без отдельной таблицы | [05-orders.md](05-orders.md), раздел 4 | Отдельная таблица при необходимости аналитики/аудита |

Правило: упрощение закрывается только по решению (ADR) с обоснованием, когда оно реально мешает эксплуатации — «профилактическое» усложнение не планируется.

## 5. За рамками v1 (направления-кандидаты)

Расширения, потенциально полезные проекту. Не планируются; каждое требует отдельного решения (ADR) перед началом работ.

| Направление | Зачем может понадобиться | Триггер |
|---|---|---|
| Push/SMS-уведомления о статусах заказа | Клиент узнаёт о статусах без ручного опроса | Начало реальной эксплуатации |
| Веб-админка (SPA) | Удобное управление каталогом с десктопа | Админ-функции неудобны в мобильном |
| Elasticsearch | Поиск на больших каталогах (морфология, фасеты) | Рост каталога, неудовлетворительное качество pg_trgm |
| Несколько складов | Остатки по филиалам | Расширение продаж |
| Мультивалюта / скидочные кампании | Новые ценовые модели | Бизнес-требования |
| Двухфакторная аутентификация | Защита аккаунтов | Безопасность станет приоритетом |
| Отдельный read-модель/сервис каталога | Масштабирование чтения | Критерии из [01-architecture.md](01-architecture.md), раздел 2 |
