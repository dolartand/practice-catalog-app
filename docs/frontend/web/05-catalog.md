# 05. Каталог: товары, SKU, изображения, категории

> Статус: Документация готова
> Версия: 0.1
> Связанные документы: [03. Интеграция с API](03-api-integration.md), Backend [03. API §4](../../backend/03-api-design.md)

## 1. Товары — список (`/products`)

AntD Table (управляемая пагинация) над `GET /products`.

Колонки: превью `mainImageUrl` (48×48), название (+артикул под ним), серия,
тип, цена (со скидкой, старая зачёркнута при скидке), рейтинг, наличие
(бейдж по `inStock`), действия (Редактировать / Удалить).

Тулбар:

- Поиск `q` (debounce 400 мс, по названию/артикулу/серии).
- Select категории (дерево из `/categories`, `categoryId` включает подкатегории).
- Фильтры: серия (`series`), тип (`type`), «в наличии» / «со скидкой».
- Сортировка: `newest | price_asc | price_desc | rating_desc | discount_desc`.
- Кнопка «Создать товар».

Действие «Удалить» → `Modal.confirm` («товар будет скрыт из каталога;
восстановление — через включение активности после расширения API») →
`DELETE /admin/products/{id}` → инвалидация.

> ⚠️ Пробел бэкенда [03 §6.1]: неактивные товары в списке не отображаются.
> В тулбаре — постоянная пометка «Показаны только активные товары», пока
> флаг `features.gaps.adminProductList` выключен.

## 2. Товар — создание и редактирование

Маршруты `/products/new` и `/products/:id` используют одну форму.

Секции формы (AntD Form, вертикальная раскладка):

| Секция | Поля |
|---|---|
| Основное | категория* (TreeSelect), название* (≤300), артикул* (≤64, уникальный), описание (textarea) |
| Классификация | серия*, тип изделия*, декор, материал |
| Габариты и вес | capacityMl, weightG, dimensions (строка), страна происхождения, штрихкод |
| Цена | priceCents* (MoneyInput, копейки), discountPercent (0–90) |
| Состояние | isActive (Switch, по умолчанию on) |

- Создание: все поля одним `POST /admin/products`; ответ — adminCard →
  redirect на `/products/:id`.
- Редактирование: форма префиллится из `GET /products/{id}`; отправляются
  только изменённые поля (`PATCH`). После сохранения — invalidate + message.
- Ошибки полей (`errors` Problem Details) → `form.setFields`.
- Цену со скидкой считаем и показываем превью на клиенте
  (`priceCents × (100 − discount)/100`, округление как у бэкенда).

Удаление — кнопка опасной зоны в шапке карточки с подтверждением.

## 3. SKU (варианты)

Блок внутри карточки товара — таблица вариантов + кнопка «Добавить вариант».

Колонки: название, артикул, цена, скидка, цена со скидкой (расчёт),
остаток (InputNumber, inline-редактирование), активен (Switch),
действие «Деактивировать» (= DELETE).

- Создание: модалка `POST /admin/products/{id}/skus`.
- Изменение цены/скидки/остатка — инлайн-редактирование строки →
  `PATCH /admin/skus/{id}` (отправляем только изменённое).
- Деактивация скрывает вариант из продажи; активация — тем же PATCH
  (`isActive: true`).
- Правило остатков: `stockQty ≥ 0`, integer; отрицательные отклоняет и бэкенд,
  и форма.
- Если SKU один — он считается «базовым»; UI выбора варианта на витрине
  появляется автоматически (>1 активных SKU).

## 4. Изображения

Блок галереи внутри карточки товара.

- Загрузка: AntD Upload (drag-zone), файлы JPEG/PNG/WebP ≤10 МБ — проверка до
  отправки; каждая загрузка → `POST /admin/products/{id}/images`
  (multipart `file`, опционально `position`, чекбокс «Сделать главным»).
- Сетка миниатюр с порядковыми номерами; перетаскивание меняет порядок —
  сохраняем последовательностью `PATCH /admin/images/{id} {position}`.
- «Сделать главным» → `PATCH {isMain: true}` (бэкенд снимает флаг с прежней).
- Удаление → confirm → `DELETE /admin/images/{id}`.
- Первая загруженная картинка автоматически становится главной
  (`isMain: true` при upload) — иначе у товара нет превью в списках.

## 5. Категории (`/categories`)

AntD Tree + панель редактирования выбранного узла.

- Дерево строится из `GET /categories` (активные); узел: имя, slug, sortOrder.
- Создание корневой/дочерней: модалка `{name ≤200, slug (уникальный, a-z0-9-),
  parentId?, description?, imageUrl?, sortOrder}` → `POST /admin/categories`.
- Редактирование узла: те же поля + `isActive` → `PATCH /admin/categories/{id}`;
  перенос узла drag-and-drop по дереву → `PATCH {parentId}` (циклы блокируем
  на клиенте + сервер вернёт ошибку).
- Удаление: confirm c предупреждением про `409` (есть активные товары или
  подкатегории) → `DELETE /admin/categories/{id}`; при 409 показываем detail
  от сервера.

> ⚠️ Пробел [03 §6.2]: скрытые (`isActive=false`) категории исчезают из дерева
> и недоступны для повторного включения до расширения API
> (`GET /admin/categories/tree`). В UI выводим предупреждение в момент
> скрытия категории.

## 6. Состояние и кэш

- Запросы списков — keepPreviousData (плавная пагинация без мигания таблицы).
- После каждой мутации — инвалидация по матрице [03 §5].
- Черновики форм не сохраняем (решение из обзора).

## 7. Права и краевые случаи

- Все операции требуют ADMIN; 401 обрабатывается глобально, 403 — notification.
- Параллельное редактирование двумя админами: последний PATCH побеждает по
  полям; конфликтные случаи (удалён другим админом) → 404 → сообщение и
  возврат к списку.
- Товар без изображений допустим (плейсхолдер в таблицах).
- Slug/артикул дубликаты → 409 с текстом от сервера в форме.
