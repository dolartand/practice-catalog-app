## 1. Назначение

Внутренняя SPA для администраторов фарфорового завода: управление каталогом
(товары, SKU, изображения, категории), обработка заказов (смена статусов),
модерация отзывов, сводный дашборд.

Пользователи — сотрудники завода, роль `ADMIN` (создаётся сидером бэкенда из
`AdminProperties`). Регистрация самостоятельная не предусмотрена.

## 2. Стек (решено)

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | **Vite + React 18 + TypeScript** | быстрый дев-сервер, стандарт для внутренних SPA |
| Маршрутизация | **React Router v6** (data router) | вложенные layout'ы, loaders не требуются |
| Серверное состояние | **TanStack Query v5** | кэш, инвалидация после мутаций, retries, devtools |
| UI-библиотека | **Ant Design 5** | Table/Form/Upload/Modal/Tree «из коробки» — минимум своего UI для CRUD |
| HTTP | **axios** | интерцепторы auth/refresh, единая обработка Problem Details |
| Формы | **AntD Form** + собственные правила | валидация зеркалит бэкенд (см. лимиты в 03) |
| Стили | AntD theme token'ы | кастомизация под бренд минимальна |

Состояние приложения — серверный кэш (Query) + лёгкий auth-контекст; глобальный
стейт-менеджер (Redux/Zustand/MobX) **не используется**.

## 3. Охват v1

1. **Аутентификация** — логин по email/пароль (`POST /auth/login`), авто-refresh,
   выход; всё под ролью ADMIN.
2. **Каталог** — товары: таблица с поиском/фильтрами, создание/редактирование
   (все поля контракта, цены в копейках), soft delete, вкл/выкл активности;
   SKU: цены/скидки/остатки, деактивация; изображения: загрузка multipart,
   порядок, главное; категории: дерево CRUD.
3. **Заказы** — таблица всех заказов с фильтром по статусу, карточка заказа,
   переходы статусов `NEW → CONFIRMED → DELIVERED` / отмена (матрица бэкенда).
4. **Модерация отзывов** — очередь неодобренных, одобрить/скрыть.
5. **Дашборд** — сводка: активные товары, заказы по статусам, отзывы на
   модерации (агрегируется из `total` пагинационных конвертов, без нового
   эндпоинта).

Вне скоупа v1: пользователи/роли, экспорт/импорт, аналитика продаж,
мультивалюта, тёмная тема, i18n (**интерфейс только русский**).

## 4. Ключевые решения

- **API без изменений на старте**: используем текущий контракт `/api/v1`.
- **Известные пробелы бэкенда** зафиксированы как блокеры/деградации в
  [03 §6](03-api-integration.md): нет админского списка товаров (включая
  неактивные), нет полного дерева категорий, нет состава заказа у оператора,
  в отзывах модерации нет имён. Бэкенд будет расширен позже отдельной задачей;
  ожидаемые контракты уже описаны в доках, чтобы реализация админки
  подключала их точечно.
- **Деньги** — целые копейки (`priceCents`); форматирование в рублевом
  представлении только на границе UI.
- **Ошибки** — RFC 9457 Problem Details → AntD notification; ошибки полей
  (`errors`) прокидываются в форму по имени поля.
- **Язык кода/коммитов** — как в мобильном репо: коммиты англ., conventional.

## 5. Открытые вопросы

1. Деплой: отдельный домен или путь `/admin` на хосте API (решается при
   настройке окружения, на дизайн не влияет).
2. Нужны ли черновики форм (автосохранение недозаполненного товара) —
   предположительно нет, вернёмся после первых сессий эксплуатации.
