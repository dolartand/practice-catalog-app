# 04. Аутентификация админки

> Статус: Документация готова
> Версия: 0.1
> Связанные документы: [03. Интеграция с API](03-api-integration.md), Backend [04. Аутентификация](../../backend/04-auth.md)

## 1. Модель

Единый механизм бэкенда для USER и ADMIN: email+пароль → пара токенов
(access ~короткий TTL, refresh с ротацией), `Authorization: Bearer`.
Админка отличается только проверкой роли: после логина читаем профиль
`GET /auth/me`; если `role !== 'ADMIN'` — сессию закрываем, показываем
«Доступ только для администраторов».

Роль из JWT не парсим (не доверяем клиентскому разбору) — источник истины
`GET /auth/me`.

## 2. Хранение токенов

| Токен | Хранилище | Обоснование |
|---|---|---|
| accessToken | память (модуль-переменная axios-слоя) | недоступен XSS-скриптам со страницы при перезапуске |
| refreshToken | `localStorage` (`admin.refreshToken`) | переживает F5; риск XSS принимаем для внутреннего инструмента (альтернатива httpOnly-cookie потребовала бы менять бэкенд) |
| user | `localStorage` (кэш профиля для мгновенного рендера) | обновляется после каждого `/auth/me` |

Выход/истечение: ключи удаляются, состояние → неавторизовано.

## 3. Refresh-flow (как в мобильном приложении)

1. Любой запрос получил 401 (и это не `/auth/*`) → помечаем запрос `_retry`.
2. Если refresh уже идёт — ждём из очереди; иначе единственный
   `POST /auth/refresh { refreshToken }`.
3. Успех → новые токены сохраняются, все ожидающие повторяются.
4. Неудачный refresh или `401` на самом refresh → logout:
   очищаем хранилища, редирект `/login?from=…`, notification «Сессия истекла».

## 4. Потоки экрана входа

```
/login
  ├── форма: email, пароль (AntD Form, autocomplete)
  ├── submit → POST /auth/login
  │     ├── ok → GET /auth/me → role=ADMIN?
  │     │      ├── да  → сохранить user, redirect на ?from | /dashboard
  │     │      └── нет → POST /auth/logout + ошибка «Только для администраторов»
  │     └── 400/401 → ошибки полей / «Неверный email или пароль»
  └── если сессия уже валидна → сразу redirect /dashboard
```

Забытый пароль — вне v1 (восстановление силами владельца аккаунта через
смену пароля после входа; отдельного эндпоинта нет).

## 5. Guard маршрутов

`RequireAdmin` оборачивает защищённые маршруты:

- нет refreshToken и нет памяти о сессии → `<Navigate to="/login" />`;
- есть refreshToken, но профиль ещё грузится → спиннер полного экрана;
- профиль загружен, роль ≠ ADMIN → экран «Нет доступа» + кнопка «Выйти».

## 6. Сессии и безопасность

- Кнопка «Выйти»: `POST /auth/logout {refreshToken}` (отзыв текущей сессии),
  затем локальный logout. «Выйти везде» (`logout-all`) — в v1 не показываем,
  эндпоинт существует, добавим по запросу.
- Idle-timeout на клиенте не делаем; доступ контролируется временем жизни
  refresh-токена на бэкенде.
- Все запросы к `/admin/**` сервер дополнительно защищает `hasRole('ADMIN')`
  — фронтовый guard это UX, а не защита.
