# 07. Заказы: оформление и история

> Статус: Реализовано (блок 7)
> Версия: 0.1
> Связанные документы: [06. Корзина](06-cart.md), [03. Интеграция с API](03-api-integration.md), [Backend 05. Заказы](../../backend/05-orders.md)

## 1. Сущность

- `entities/order`: типы под реальные статусы `NEW / CONFIRMED / DELIVERED / CANCELLED`, поля заказа по контракту.
- `OrderStore`: fetchList, fetchOne, create, cancel.

## 2. Оформление заказа (features/checkout)

- Форма: customerName, customerPhone, deliveryCity, deliveryAddress, comment.
- Локальное автозаполнение из последнего успешного заказа (kvStorage — не серверная адресная книга).
- Обработка ошибок: **422** — список недоступных позиций; **409** — конфликт.

## 3. Экраны

| Экран | Назначение |
|---|---|
| pages/checkout | оформление; при 422 показывает недоступные позиции (см. [03](03-api-integration.md)) |
| pages/order-history | «Мои заказы» во вкладке профиля |
| pages/order-detail | детали заказа, отмена при статусе NEW |

Разделение истории на «Текущие» (все не DELIVERED) / «Прошлые» (DELIVERED) — **клиентское, визуальное**: `GET /orders` не имеет параметра фильтрации по статусу, серверная пагинация остаётся без изменений.

**Критерий приёмки**: полный путь корзина → оформление → отслеживание статуса → (при NEW) отмена работает.
