# Блок 8 — Избранное

Зависит от: блок 1 (токен), блок 2 (ProductListItem/карточки).

Документ-план перед реализацией. Опирается на фактический контракт бэкенда
(`FavoriteController` / `FavoriteService`), чтобы на фронте не появилось того, чего бэкенд не умеет.

---

## 1. Контракт бэкенда (источник истины)

Базовый путь: `/api/v1/favorites`. **Все три эндпоинта требуют авторизации**
(`SecurityConfig`: `anyRequest().authenticated()` → без токена 401).

| Метод | Путь | Ответ | Поведение |
|---|---|---|---|
| `PUT` | `/favorites/{productId}` | `204 No Content` | Добавить. Идемпотентен: если уже в избранном — тихий no-op. Если товара нет/удалён — `404` |
| `DELETE` | `/favorites/{productId}` | `204 No Content` | Удалить. Идемпотентен: если записи нет — тихий no-op |
| `GET` | `/favorites?page=0&size=20` | `PageResponse<ProductSummaryResponse>` | Список, сортировка `createdAt DESC` (сначала добавленные последними). `size` клампится бэкендом в `[1..100]` |

Тело элемента списка — `ProductSummaryResponse`, структурно идентичное уже используемому
на фронте `ProductListItem`:

```json
{
  "id": "uuid", "name": "...", "article": "...", "series": "...", "productType": "...",
  "priceCents": 0, "discountPercent": null, "priceWithDiscountCents": 0,
  "mainImageUrl": null, "ratingAverage": 0, "ratingCount": 0, "inStock": true
}
```

Конверт пагинации стандартный: `{ items, page, size, total, totalPages }` (`PageEnvelope`).

### Важные нюансы серверной реализации

1. **Нет эндпоинта «проверить один товар»** (нет `GET /favorites/{productId}`, нет
   `GET /favorites/ids`). Узнать, в избранном ли товар, можно только вытянув список
   постранично → фронт обязан сам держать локальный Set id избранного.
2. **Удалённые/неактивные товары молча выбрасываются из выдачи** (`summariesByIds`
   фильтрует `isDeleted || !isActive`) → страница может вернуть меньше элементов, чем
   `size`, а `total` при этом их считает. Фронт не должен считать это ошибкой.
3. Оба мутационных эндпоинта идемпотентны и возвращают пустое тело → двойные тапы и
   гонки безопасны; синхронизировать после ответа нечего (в отличие от корзины).

## 2. Что бэкенд НЕ поддерживает → чего НЕ будет на фронте

- Нет batch-добавления/удаления → тоггл строго поштучно.
- Нет фильтров/поиска/сортировки внутри избранного → на странице только список + пагинация.
- Нет счётчика избранного отдельным эндпоинтом → бейдж таба считаем по локальному Set
  (`favoriteStore.count`), без лишних запросов.
- Нет «поделиться избранным», нет списков/wishlists → один плоский список.

```
src/

│   ├── model/types.ts             # FavoriteProduct (зеркало ProductSummaryResponse)
│   ├── model/favorite.store.ts    # MobX: items+пагинация, favoriteIds Set, pendingIds
│   └── index.ts
├── core/bootstrap/

│   └── index.ts

```

Правила границ (eslint-plugin-boundaries) учтены:
- `entities/favorite` не может импортировать `entities/product` → заводим свой тип
  `FavoriteProduct` (структурно совместим с `ProductListItem`, поэтому карточка
  принимает его без конвертации).
- `ProductCard` лежит в entities и не может тянуть feature → вместо этого даём ему
  необязательный слот `action?: ReactNode` поверх изображения; композиция — в слоях
  widgets/pages (`CatalogPage` прокидывает `<ToggleFavoriteButton/>` через новый
  опциональный проп `renderItemAction` у `ProductGrid`). Оба пропа опциональны —
  существующие вызовы не ломаются.

## 4. FavoriteStore — ключевые решения

Состояние:
- `items: FavoriteProduct[]`, `page/size/total/totalPages` — данные для экрана «Избранное»
  (пагинация как у каталога: `fetch()` сброс на страницу 0, `fetchMore()` по `hasNextPage`).
- `favoriteIds: Set<string>` — быстрый ответ на вопрос «в избранном ли товар» для любых
  сердечек в приложении (каталог, поиск, детальная).
- `pendingIds: Set<string>` — тогглы «в полёте» (на время запроса лёгкое приглушение кнопки).
- `isLoading / isLoadingMore / error` (`'favorites_load_failed'` → ключ i18n).

Поведение:
1. **Optimistic toggle** (`toggle(productId)`): мгновенно меняем `favoriteIds`
   (+ вставляем item в начало `items`, ведь сервер сортирует по createdAt DESC) → шлём
   `PUT`/`DELETE`; при ошибке откатываем состояние и пробрасываем исключение.
   Идемпотентность бэкенда делает повторные запросы безопасными.
2. **Гидрация**: `init()` (вызывается из bootstrap-reaction при входе/восстановлении
   сессии): мгновенно поднимаем кэш id из kvStorage (`favorites.ids:{userId}`) — сердечки
   верны сразу с холодного старта, затем полная синхронизация с сервером (GET со
   `size=100`, циклом добираем страницы до `totalPages`, потолок 500 позиций) и перезапись
   кэша. Ключ кэша включает userId — аккаунты на одном устройстве не подмешивают друг друга.
3. **Реконсиляция**: каждый успешный GET списка добавляет вернувшиеся id в Set
   (частичная страница ничего не удаляет из Set — см. нюанс 2 выше; авторитетная
   перестройка — только fullSync в `init()`).
4. `reset()` при логауте: очищает всё + удаляет кэш.

Критерий блока «переживает перезапуск» закрывается дважды: сервером (после refetch) и
локальным кэшем (до ответа сети — мгновенно и без мигания сердечек).

## 5. UI/UX и дизайн (современный стиль, libs из package.json)

- **ToggleFavoriteButton** (lucide `Heart` + react-native-reanimated):
  круглая стеклянная кнопка (полупрозрачный тёмный фон, как back-кнопка на детальной),
  пружинное масштабирование при нажатии (withSpring) и bounce-пульс при переключении;
  активная — заливка `theme.colors.danger`, неактивная — контур. Цвета через unistyles
  theme → работает в светлой/тёмной теме.
  Неавторизованный тап → **тост-подсказка** «Войдите, чтобы добавлять в избранное»
  (навигацию не дёргаем). Для этого заведён минимальный централизованный тост:
  `shared/lib/toast.ts` (эмиттер) + `shared/ui/toast/ToastHost` (плашка поверх
  приложения, монтируется один раз в `app/_layout.tsx`) — дальше на нём же поедут
  ошибки корзины и прочие уведомления.
- **Расположение сердечка**: карточка — правый нижний угол изображения (верх занят
  бейджами скидки/«нет в наличии»); детальная — справа сверху над галереей, зеркально
  back-кнопке.
- **Страница «Избранное»**: корень таба — без back-кнопки, крупный заголовок (large
  title), сетка 2 колонки из переиспользуемых `ProductCard` (с сердечками), скелетоны
  (`ProductCardSkeleton`), пустое состояние (крупный Heart + подпись-подсказка +
  CTA-кнопка «Перейти в каталог»), footer-spinner при догрузке, RefreshControl.
  Нажатие → детальная страница товара. Список обновляется при каждом возврате на экран
  (`useFocusEffect` → `fetch()`), а не только при первом открытии.
- **Точка входа — отдельный таб** (Каталог · Избранное · Корзина · Профиль): Heart-иконка,
  бейдж с количеством из `favoriteStore.count` (обновляется мгновенно при тогглах, стиль
  как у бейджа корзины). Гость видит таб, но при входе AuthGuard уводит на логин.
  В блоке 10 меню профиля всё равно получит пункт «Избранное» — дублирование ссылки
  в текущем Settings убрано.

## Принятые решения по итогам обсуждения

1. Локальный кэш id в kvStorage — оставляем (ключ `favorites.ids:{userId}`, очистка при логауте).
2. Полная синхронизация Set при входе — до 500 позиций (5 страниц × 100, потолок бэкенда — 100/страница).
3. Экран «Избранное» обновляется на каждом фокусе (`useFocusEffect`).
4. Гость при тапе на сердечко получает тост-подсказку (не редирект); централизованные
   тосты ошибок — задача блока 11, текущий ToastHost задел под неё.
5. Сердечко на карточке — правый нижний угол изображения.
6. В пустом состоянии — CTA «Перейти в каталог».
7. Избранное — отдельный таб внизу с бейджем-счётчиком (не ссылка в профиле).

## 7. Критерий приёмки

- [ ] Сердечко на карточке каталога и на детальной переключается мгновенно (optimistic),
      при ошибке сети — откат к прежнему состоянию.
- [ ] После убийства и перезапуска приложения состояния сердечек корректны сразу
      (кэш) и подтверждены сервером после гидрации.
- [ ] Таб «Избранное» доступен только авторизованному (AuthGuard), показывает
      список с пагинацией; удалённые с сервера товары просто исчезают из выдачи.
- [ ] Бейдж на табе показывает актуальное количество и обновляется мгновенно.
- [ ] Тоггл из каталога и со страницы избранного согласован везде (один Store/Set).
- [ ] Логаут чистит локальные данные избранного; вход другого аккаунта не видит чужой кэш.
