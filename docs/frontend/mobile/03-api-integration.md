# 03. Интеграция с API

> Статус: Реализовано (блок 0)
> Версия: 0.1
> Связанные документы: [04. Auth](04-auth.md), [Backend 03. Проектирование API](../../backend/03-api-design.md), [Контракт API](../../backend/openapi.yml)

## 1. HTTP-клиент

- Базовый URL: `/api/v1`.
- Интерцептор `X-Request-Id`: UUID на каждый мутирующий запрос (POST/PATCH/DELETE) — сквозная трассировка с бэкендом.
- Все ответы бэкенда принимаются без адаптации на уровне фич — нормализация происходит в клиенте.

## 2. Обработка ошибок: Problem Details → AppError

RFC 7807 `application/problem+json` нормализуется в единый тип:

```ts
AppError {
  type,      // URI-идентификатор типа ошибки
  title,     // человекочитаемый заголовок
  status,    // HTTP-статус
  detail,    // описание
  errors     // поле → сообщение (для валидации форм, 400/422)
}
```

`errors` используется формами (login/register/change-password/checkout) для подсветки конкретных полей.

## 3. Аутентификационные интерцепторы

- Access token прикрепляется к каждому запросу.
- Схема обновления при 401: попытка refresh → очередь отложенных запросов → повтор; при неудаче refresh — разлогин и сброс SessionStore (подробно в [04-auth](04-auth.md)).

## 4. Особые статусы

| Статус | Сценарий | Поведение UI |
|---|---|---|
| 401 | истёкший access | тихий refresh, пользователь не замечает |
| 403 | нет права (например, на отзыв) | понятное сообщение, без сырого текста |
| 409 | конфликт (оформление заказа и др.) | сообщение из Problem Details |
| 422 | нехватка склада при оформлении заказа | список недоступных позиций с именами из корзины |

## 5. 422: расширение Problem Details для нехватки склада

Source of truth — код бэкенда (`GlobalExceptionHandler.handleInsufficientStock`); в `openapi.yml` это расширение пока **не описано** (задача на сторону бэкенда).

```json
{
  "type": "about:blank",
  "title": "Unprocessable Entity",
  "status": 422,
  "detail": "Insufficient stock for N item(s)",
  "traceId": "...",
  "items": [{ "skuId": "…", "requested": 2, "available": 0 }]
}
```

Клиент парсит `items` в `AppError.stockIssues` (`shared/api/problem-details.ts`). При получении таких позиций checkout показывает список «товар: запрошено X, доступно Y» (имена берутся из корзины по `skuId`) и перезапрашивает корзину — бэкенд помечает проблемные позиции флагом `unavailable`.
